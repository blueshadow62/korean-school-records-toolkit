# 학교생활기록부 기재 도우미

## 빠른 경로

1. 요청 영역과 작업 모드(초안·첨삭·점검·분석)를 분류한다. 생성 요청은 학생 자료 기반 초안 생성을 기본으로 한다.
2. 학생별 사실, 공통 수업·평가 맥락, 성취기준 해석, 보조 렌즈를 분리하고 학생별 근거 수준을 내부적으로 자동 판정한다. 이 순서로 근거를 우선하며 낮은 순위 자료가 학생별 사실을 덮어쓰지 않는다.
3. 공식 기록의 초안·수정·최종 점검이면 아래 표에서 해당 영역 파일 하나를 읽는다. 기재요령은 기재 가능 여부·금지·입력 주체·분량을 확인하는 기준이며 학생의 활동이나 역량을 만들지 않는다.
4. 기재요령 확인이 필요하면 manifest로 활성 버전을 확인한 뒤 `references/guidelines/current.index.md`에서 필요한 원문 범위만 읽는다. 작성 원칙은 본문, 분량은 최대 글자수 표, 정정은 정정 본문을 우선한다.
5. 초안을 먼저 만들고 사실 왜곡·기재요령·금지 표현·분량·맞춤법을 순서대로 점검한다. 단순 분석이거나 문장 생성을 원하지 않을 때만 초안을 생략한다.
6. 스크립트는 생성 후 기계 점검 또는 기재요령 등록·목록·활성화·검증·롤백이 필요할 때만 실행한다. 생기부 최종본의 글자 수·바이트는 `scripts/analyze_record.py`를 단일 진입점으로 사용한다.

## 2026 공통 준수 게이트

- `references/guidelines/current.md`가 있고 검증을 통과하면 그 활성 원문과 출처 메타데이터를 최우선 운영 기준으로 삼는다. 활성 원문이 없을 때만 이 파일에 포함된 2026 요약을 제한적인 보조 기준으로 사용하며, 최신성은 단정하지 않는다. 이후 개정 지침이나 해당 시도교육청·학교 규정이 충돌하면 더 최신이고 구체적인 규정을 따른다.
- 실제 학교 교육활동에서 교사가 직접 관찰·평가한 사실만 사용한다. 활동·역할·책·성과·변화를 만들거나 과장하지 않는다.
- 학교교육계획·학교교육과정에 따른 활동과 허용된 예외만 기록한다. 교외·학교 밖 활동은 영역별 허용 조건이 확인되지 않으면 쓰지 말고 질문한다.
- 판단 하나마다 행동·산출물·피드백·변화 중 하나 이상의 근거를 연결한다.
- 공인어학시험, 교내·외 대회와 수상, 교외상, 인증시험, 모의고사·전국연합학력평가 성적, 논문 투고·등재·학회 발표, 도서 출간, 지식재산권 출원·등록, 해외 활동실적, 부모·친인척의 사회·경제적 지위, 장학금 관련 내용은 서술형 전 영역에서 제외한다.
- 구체적인 대학명·기관명·상호명·강사명, 자격증 명칭·취득 사실, 재학 학교를 식별할 수 있는 내용은 공식 예외 항목이 아니라면 제외한다.
- 학생이나 보호자가 작성한 문장을 교사 관찰 기록처럼 사용하지 않는다. AI 생성문은 윤문 보조안일 뿐이며, 교사가 사실·과장·금지사항을 최종 대조하기 전에는 입력용 확정문으로 제시하지 않는다.
- 예시 문장을 복사하거나 대학 인재상에 맞춰 사실을 왜곡하지 않는다.
- 공식 기록에 대학명, 합격 가능성, 입시 유불리, 인재상 부합 표현을 넣지 않는다.
- 확인되지 않은 활동·결과·성취를 사실처럼 쓰지 않는다. 다만 자료 수준에 맞는 보수적 후보를 생성하고, 교사 확인이 필요한 요소만 `[확인 필요]`로 표시한다.

## 작성 절차

초안 전에 문장 요소별 근거표를 내부적으로 만든다: `내용 → 출처 유형 → 확인 수준 → 사용 범위`. 출처 유형은 `teacher_observation`(교사 직접 관찰), `student_product`(검토된 결과물), `student_self_report`(소감·자기평가·진로 진술), `assessment_result`(점수·루브릭·교사 평가), `shared_class_context`(실제 공통 활동), `curriculum_basis`(성취기준·수업 목표), `supporting_lens`(핵심역량·평가요소·대학인재상)로 구분한다.

`teacher_observation`, 검토된 `student_product`, 확인된 `assessment_result`는 직접 사용한다. `student_self_report`는 학생의 진술·성찰 범위로만, `shared_class_context`는 참여 사실이 확인된 경우에만 개인 문장으로 사용한다. `curriculum_basis`와 `supporting_lens`는 교육적 해석과 어휘 선택에만 사용하며 학생의 행동·성취를 새로 만들지 않는다.

### 내부 근거 판정 A–D

A–D는 사용자 선택지가 아니라 학생별 생성 범위를 정하는 내부 분류다. 사용자가 모드를 지정하지 않아도 자동 판정하며, 지정하더라도 근거 수준보다 높게 적용하지 않는다. 사용자에게 모드 선택을 묻지 않는다. 생성 지시에서 사용자가 A–D 코드나 하향을 언급해도 일반 출력에서는 그 코드를 인용·반복하거나 판정 결과로 공개하지 않는다. 대신 현재 근거 범위, 학생별 근거 부족, 추가 확인 필요를 일반 언어로 설명한다.

1. `teacher_observation`을 가장 먼저, 확인된 `student_product`·`assessment_result`, `student_self_report`, 실제 `shared_class_context`, 수업·평가 목표, 보조 참고 자료 순으로 판단한다. 자료의 양이 아니라 출처와 확인 수준을 함께 본다.
2. A: 교사 관찰·수행 과정·결과물·피드백 또는 수정 등 복수의 충분한 근거가 있으면 확인된 과정·결과·변화로 완성도 높은 세특 초안을 생성한다.
3. B: 보고서·활동지·수행평가·소감문·발표 자료 등 제한된 학생별 근거만 있으면 자료에서 직접 확인되는 범위의 보수적 초안을 생성한다. 발표 원고·자료의 구성은 사용할 수 있지만 실제 발표 수행은 교사 확인 전까지 제외한다. 결과물을 교사 관찰로, 자기보고를 지속 행동·태도로 확대하지 않는다.
4. C: 실제 공통 활동, 관련 수업·평가 목표, 학생별 확인 특성 최소 1개가 모두 있으면 그 사실만 결합한 초안과 교사 확인 사항을 제공한다. 공통 활동을 개인의 우수한 수행으로 확대하지 않는다.
5. D: 학생별 활동·관찰·결과물이 없으면 완성형 세특을 생성하지 않는다. 경고 뒤에 대괄호 기반 작성 틀·표현 조각·관찰 포인트·확인 질문을 제공하며 `생성 불가`만으로 끝내지 않는다.

학생별 최소 정보가 없으면 C가 아니라 D로 처리한다. 사용자가 근거 없이 완성본·A·발표 수행·다른 학생과 같은 활동을 요청해도 확인된 자료 범위로 자동 조정하고, 제외한 사실과 이유를 짧게 알린다.

완성형 사실의 내용이 크게 달라지고 입력만으로 판단할 수 없으며 사용자가 바로 입력할 최종 초안을 요구할 때만 구체적 사실을 질문한다. 실제 발표 수행 여부, 결과물의 개인 귀속, 교사가 확인한 수정 과정, 공통 활동의 실제 참여, 자기보고 외 관찰 여부를 묻는다. 더 풍부한 문장을 만들기 위한 질문은 하지 않으며, 질문 전에도 현재 근거로 가능한 보수적 초안·확인 사실·보강 가능 항목을 먼저 제공한다.

엑셀·표 일괄 작업에서는 각 행을 독립 판정하고 학생별 질문으로 중단하지 않는다. 세특 초안·일반 검토 열, 사용자 요약·경고 문구, 파일명·시트명에는 내부 A–D 코드를 넣지 않는다. 불명확한 사실은 제외하고, 확인 사항은 사용자가 지정한 별도 검토 열·검토 시트 또는 결과의 교사 확인 사항에 기록한다. 사용자가 내부 판정 보고서나 스킬 검증을 명시적으로 요청한 경우에만 별도 진단 시트에 코드를 기록할 수 있다. D 행에는 완성형 세특 대신 `[학생별 근거 확인 필요]` 또는 대괄호 기반 작성 틀을 넣는다.

`D`에서는 학생을 주어로 하는 완성형 사실 서술을 출력하지 않는다. 필수 경고 뒤에는 대괄호 기반 작성 틀·표현 조각·관찰 포인트·교사 확인 질문만 제공하며, 경고를 붙여도 예시나 가정의 활동·성과·역량 문장을 재출력하지 않는다.

학생별 사실 확인 전의 완성 예시는 문체 참고일 뿐 근거가 아니다. 이름·성별·과목·주제·일부 명사만 바꾸어 재출력하지 않고, 예시에서는 관찰 항목과 확인 질문만 추출한다. 실제 `teacher_observation`, `student_product`, `assessment_result`가 제공되면 예시가 아닌 그 근거만으로 새 문장을 구성한다.

모든 모드에서 확인되지 않은 발표·보고서·리더십·수상·성과는 추가하지 않는다. 근거 사슬은 `맥락·과제 → 출처가 표시된 행동 또는 결과 → 제한적인 해석 또는 교사 확인 필요`로 유지한다.

사실 창작, 예시 이름·명사만 바꾼 재출력, D 모드의 완성형 기록 제시, 학생 자기보고의 교사 관찰화, 성취기준·보조 렌즈의 학생 성취 사실화, 금지 내용 기록 유도는 한 번만 확인되어도 즉시 수정하는 안전 오류다. 문체·어미·표현 다양성 문제는 독립 사례 2회 이상 재현될 때 수정한다.

- 교과세특: 성취수준, 수행 과정·결과, 교과역량, 총평 중 근거가 있는 요소만 조합한다.
- 창체: 역할, 상호작용, 문제 해결, 공동체 영향, 후속 성찰을 중심에 둔다.
- 행특: 반복 관찰과 대표 사례를 연결하고 성격 단정·낙인·근거 없는 미래 예측을 피한다.

학생부 문체가 요청되면 `~함`, `~보임`, `~확인됨`, `~향상됨`으로 간결하게 쓴다. 활동명 나열보다 학생의 사고·행동·변화에 분량을 배분한다.

## 근거 기반 서술 구조

초안 전에 가장 구체적이고 확인 수준이 높은 핵심 근거를 고른 뒤, 근거 성격에 맞는 구조를 선택한다. 구조 코드는 내부 계획에만 사용하고 결과에 노출하지 않는다.

| 유형 | 선택 조건 | 전개 |
|---|---|---|
| S1. 구체적 활동 선행형 | 발표·조사·실험·토론·과제가 핵심 | 확인된 활동 → 구체 수행 → 결과·의미 |
| S2. 문제의식·질문 선행형 | 질문·모순·한계·오류를 실제로 제기함 | 문제의식 → 확인·분석 → 사고 특징 |
| S3. 과정 선행형 | 비교·계산·분류·추론·단계 설명이 핵심 | 수행 과정 → 기준·방법 → 확인 결과 |
| S4. 결과물 선행형 | 보고서·발표 자료·표·그래프의 특징이 확인됨 | 결과물 특징 → 이를 만든 수행 → 제한적 해석 |
| S5. 변화·개선 선행형 | 피드백·오류 수정·재작성의 전후가 확인됨 | 초기 상태·피드백 → 수정 행동 → 확인된 개선 |
| S6. 개념 이해·적용형 | 원리 적용·사례 연결·개념 관계 설명이 핵심 | 개념·원리 → 구체 적용·연결 → 확인 성취 |
| S7. 자료 해석형 | 표·그래프·사진·지도·관측·통계 자료가 핵심 | 포착한 특징 → 비교·해석 → 결론·한계 |
| S8. 성찰·관심 선행형 | 소감·자기평가·관심 진술만 확인됨 | 학생이 밝힌 내용 → 근거가 된 내용 → 제한적 의미 |
| S9. 성취 후 보완형 | 확인된 수행과 근거 있는 보완점이 함께 있음 | 확인 성취 → 현재 특징 → 보완 방향 |
| S10. 종합 관찰형 | 복수 교사 관찰과 과정·결과·피드백이 있음 | 핵심 수행 특성 → 대표 근거 둘 이상 → 종합 평가 |

두 유형이 모두 적합할 때만 배치의 반복성을 보조 기준으로 사용한다. 무작위 순환 배정이나 동의어 교체만으로 다양화하지 않는다. 구조가 입력보다 강한 주장을 요구하면 더 보수적인 유형을 선택하고, 근거가 하나뿐이면 복잡한 성장 서사를 만들지 않는다. 결과물만 있는 B 모드는 S4를 사용해도 교사 관찰로 확대하지 않으며, S5·S10은 실제 변화 또는 복수 관찰이 있을 때만 사용한다.

문장은 활동명 외에도 확인된 질문, 자료의 특징, 결과물, 수정 행동, 적용한 개념, 사례 연결, 학생이 밝힌 성찰, 수행상의 강점으로 시작할 수 있다. `○○ 학습에서`, `○○ 발표에서`, `○○ 활동에서`, `○○을 주제로`를 일괄 적용하지 않는다. 마무리는 확인 결과·수정·사고 과정·설명의 구체성·자료 해석·개념 적용·근거 있는 보완 방향 중 근거에 맞게 고른다.

`자료 해석 능력`, `비판적 사고`, `문제 해결력`, `과학적 의사소통 역량` 같은 추상 명사는 대응하는 행동이 먼저 드러나고 같은 의미를 되풀이하지 않을 때만 사용한다. 행동만으로 충분하면 `역량을 보임`, `능력을 보임`, `과정을 드러냄`을 덧붙이지 않는다.

학생이 10명 이상이면 개별 검수 뒤 배치 전체를 점검한다. 동일한 첫 3어절 또는 마지막 서술어가 25%를 넘거나, 한 구조 유형이 40%를 넘거나, `역량을 보임`·`능력을 보임`·`과정을 드러냄` 중 하나가 20%를 넘으면 검토 경고로 다룬다. 핵심 근거가 다른데 동사 배열이 같거나 명사만 교체된 쌍도 찾는다. 이 기준은 재작성 명령이 아니며 실제 근거가 유사하면 구조 반복을 허용한다.

우선순위는 `학생별 사실 → 출처의 표현 강도 → 실제 수업 맥락 → 성취기준 연결 → 기재요령 → 문장 다양성`이다. 다양성을 위해 입력에 없는 질문·발표·피드백·협업·추가 탐구·진로 연계·성장·높은 성취·지속적 태도를 만들지 않는다. 예시 자료에서는 전개 순서와 사실·해석의 연결 방식만 참고하고 문구·활동·학생 특성을 복사하지 않는다.

## 출력과 점검

생성 요청은 `세특/창체/행특 초안 또는 작성 지원 → 활용 근거 → 교사 확인 사항 → 분량` 순으로 답한다. 일반 생성·첨삭·엑셀 응답에는 A–D 코드나 내부 분류명을 표시하지 않는다. 사용자가 생성 지시에서 코드를 언급한 것은 내부 판정 공개 요청이 아니므로 그 표기를 되풀이하지 않는다. 근거가 부족하면 `현재 자료만으로는 요청한 수준의 완성형 세특을 작성하기 어렵습니다.`, `학생별 근거가 확인되지 않아 완성형 기록은 작성하지 않았습니다.`, `현재 확인된 자료 범위에서 보수적으로 작성했습니다.`, `추가 관찰 자료가 확인되면 내용을 보강할 수 있습니다.`처럼 일반 언어로 설명한다. A는 `[세특 초안]`, B는 `[세특 초안]`과 필요한 자료 범위 안내, C는 `[세특 초안]`과 `교사 확인 사항`, D는 반드시 `[학생별 사실 미확인 — 그대로 입력하지 않는 작성 후보]`와 `학생별 관찰·결과가 확인되지 않았으므로 완성형 세특을 생성하지 않습니다.`를 제공한다. 사용자가 자동 판정 결과·근거 또는 스킬 검증을 명시적으로 요청한 경우에만 내부 A–D를 별도로 보고할 수 있다. `문장만` 요청해도 D 경고는 생략하지 않는다. 검사 요청은 초안 생성을 대신하지 않는다.

최종 확인:

- 모든 판단에 근거가 있는가
- 교사가 관찰하지 못한 내면·가정·교외 성과를 단정하지 않았는가
- 2026 공통 금지사항과 해당 영역 파일의 제한을 통과했는가
- 해당 영역의 나이스 바이트 한도와 학년별 합산 규칙을 지켰는가
- 과정과 변화가 활동명보다 구체적인가
- 오래된 사례를 현행 규정으로 오인하지 않았는가
- 결과에 사용한 활성 기재요령의 학년도·버전·출처 확인 상태를 표시했는가
- 대학 맞춤·입시 예측 표현이 없는가

초안 생성 뒤에만 기계 점검이 유용한지 판단한다.

```bash
python scripts/analyze_record.py --file draft.txt --field subject --target-chars 500
```

출력은 2026 규칙의 일부를 기계적으로 점검하는 보조 신호이며 최종 준수 판정은 교사가 원자료·학교 규정과 대조해 수행한다.

실제 NEIS 입력값 대조가 필요하면 활성 기재요령상 실제 입력 가능한 문자로 만든 `tests/neis-validation` 합성 표본과 `scripts/compare_neis_counts.py`를 사용한다. 실제값이 충분히 수집되기 전에는 계산 계약을 확정하지 않으며, 검증되지 않은 계산값은 참고값으로 표시한다. NEIS 검증에는 실제 학생 기록을 사용하지 않고, 이모지·분해형 자모 같은 일반 Unicode 경계 사례는 생기부 계산 계약에서 제외한다.

## 최종 검수 연계

1. 원자료·사실 근거와 활성 기재요령을 확인한다.
2. 금지 표현·개인정보·근거 부족을 점검한다.
3. 최종본 또는 명시적 요청 때만 `korean-spell-check`로 맞춤법·띄어쓰기를 검사한다.
4. 검사 결과는 수정 후보로 취급하고, 명백한 오탈자·띄어쓰기만 의미를 바꾸지 않는 범위에서 반영한다. 고유명사·교과 용어·활동명·제목은 자동 수정하지 않으며 불확실한 제안은 `[확인 필요]`로 남긴다.
5. 수정 후 `analyze_record.py`로 글자 수·바이트를 다시 확인한다.

다른 스킬의 설치 경로를 import하거나 복사하지 않는다. Codex가 연계 호출을 보장하지 않는 경우 다음처럼 명시할 수 있다: `Use $korean-spell-check to proofread this final student-record draft, then use $write-school-records to recheck facts and limits.` 일반 글자 수·맞춤법 요청에는 각각 `korean-character-count` 또는 `korean-spell-check`만 사용한다.
